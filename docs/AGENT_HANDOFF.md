4. 修改前读对应源码和测试；不要仅凭本文换引脚、解码色序、分区或音频格式。

朋友买的是同款硬件，但 **MAC、串口、出厂分区和完整 Flash 内容仍属于各自设备**。原作者的本机路径、设备配置、全片备份和历史日志不是新设备的配置模板。不要以去掉校验、整片擦除或改 eFuse 的方式绕过工具拒绝。

## 硬件身份与不应回退的接线结论

已验证组合为 **GOOUUU ESP32-S3-CAM V1.5 主板 + S3-CAM-DevPro V2.0 底板 + ST7789 240×320 屏**。原芯片 ESP32-S3 rev v0.2，16 MB Flash、8 MB 内置 OPI PSRAM（AP_3v3）；原传感器驱动读数为 **OV3660 / `0x3660`**，商品描述的 OV2640 不能覆盖实机 PID。新板仍需读自己的容量和 PID。

主板叠插后镜头朝外，USB 口朝底板电池/开关端，天线朝喇叭端；屏幕显示面朝与镜头相反的一侧。所有装配先断开 USB/电池；喇叭接“喇叭”口，屏幕逐针核对 GND。图与原理图见[商家资料](../vendor/goouuu-s3-cam/README.md)。

| 外设 | 已核对 GPIO / 设置 |
| --- | --- |
| Camera XCLK / SDA / SCL | 15 / 4 / 5，XCLK 20 MHz |
| Camera D0…D7 | 11、9、8、10、12、18、17、16 |
| Camera VSYNC / HREF / PCLK | 6 / 7 / 13；PWDN / RESET 均为 -1 |
| Speaker I2S DOUT / BCLK / WS | 39 / 40 / 41；标准 Philips I2S；无 MCLK、无独立使能 GPIO |
| LCD MOSI / CLK / DC / RST / CS / BL | 20 / 19 / 47 / 21 / 45 / 38 |
| BOOT / 底板 BUTTON1 | GPIO0，共用一个输入；按下接地 |
| 底板 BUTTON2“预留按键” | GPIO46，按下接地，运行时 `INPUT_PULLUP` |
| 未启用麦克风 | WS1 / SCK2 / DIN42 |

硬约束与易错点：

- 屏幕占用 GPIO19/20；串口走 **CH340 / TTL USB-C**，不能同时启用原生 USB。原板 CH340 为 `1a86:7523`，原生 USB 为 `303a:1001`；端口名称不是通用常量。
- SD 的 38/39/40 与背光及音频复用，本版不使用 SD；OPI PSRAM 占用的 26–37 不应被当作空闲扩展脚。
- 相机直接使用 LEDC channel0/timer0。背光 GPIO38 用普通高低电平，避免 Arduino `analogWrite` / 自动 LEDC 分配覆盖相机时钟。
- BUTTON1 与主板 BOOT 是同网，不能绑定成两个独立控制。BUTTON2 是当前唯一新增独立键。RST/EN 和电池开关保留原功能。
- GPIO0/46 是启动配置脚；正常运行后配置上拉，不添加固定外部上拉来改变下载条件。正常 Flash 启动要求 GPIO0 高；常规下载要求 GPIO0/46 均低。
- 功放原理图没有完整型号，只能确认 MAX98357A/B 类兼容引脚，不能写成已确认 MAX98357A。电池及充电保护未完成验证；当前用 USB 供电。
- 商家 PDF 有旧屏幕尺寸文字。实际选择以 `sdkconfig` 的 `CONFIG_LCD_ST7789_240X320=y`、对应配置分支及已正常显示的实机为准。当前屏幕未实现触摸。

## 固件数据流与算法

```text
BOOT / BUTTON1 或串口 c
  → 丢弃两帧旧图，再取一张 320×240 JPEG
  → 解码为 RGB888
  → 同一份 RGB 数据：作曲 + 缩放到屏幕 240×180
  → 16 个音符 + 当前鼓点开关
  → 分块合成 PCM → I2S → 底板功放 → 喇叭
                         └→ on_sent 计数 → 扫描线/进度
```

这是本地确定性规则和轻量合成器，没有图像语义识别、云模型或音乐生成 API。相似视觉特征可能得到相似音乐；不会识别“这是一只猫”再生成猫的主题曲。

| 映射 | 当前实现 |
| --- | --- |
| 全局亮度 | `0.2126R + 0.7152G + 0.0722B`，归一化到 0–1 |
| 根音 | HSV 色相划为 12 个音级，按 `saturation × value` 投票；低饱和度/近黑不投票，完全中性回退 C，平票取较低音级 |
| 音阶 | 亮度低于 0.42 用小调五声音阶 `{0,3,5,7,10}`，否则大调五声音阶 `{0,2,4,7,9}` |
| 速度 | `round(60 + 18 × brightness + 18 × edge)`，合成端限制在 60–96 BPM |
| 时间结构 | 从左到右 16 个竖条，逐条对应半拍；两小节 4/4，共 8 拍，末尾加 100 ms 静音 |
| 音高 | 每条以亮度平方加权求纵向重心，越靠上目标音高越高；局部亮度作小幅偏移，再量化到所选音阶、MIDI48–84 |
| 力度 | 每条亮度映射为 0.35–0.9 的 velocity |
| 音色 | 每条加权颜色投票：红橙 Pluck、黄绿 Keys、青蓝 Flute、紫粉 Bell；中性/近黑条默认 Keys |
| 鼓 | 只有 Drums，默认关闭；八分音符踩镲，1/3 拍底鼓、2/4 拍军鼓；与旋律共用采样计数 |

选定音阶、固定节拍与包络让输出更容易形成连贯听感，但不保证每张照片都“好听”。v0.3.0 **没有 Bass、琶音、和弦引擎、FFT、显著性模型、SoundFont 或连续视频作曲**。

合成格式为 22050 Hz、双声道 16 位，左右相同；一次 256 帧，不分配整段音频。四音色由振荡器谐波和包络实现，不是采样乐器库。旋律及鼓分别预留混音余量，合计设计最大增益 0.171，最终防御性幅度限制 0.175；该数值不是实际喇叭响度。

鼓点开启应用到后续尚未生成的节拍边界；关闭约 8 ms 淡出，但已经排入 DMA 的声音仍会播放。重播保留当前鼓开关，复位后关闭。照片/歌曲只在内存中保存，未实现作品持久化。

## 已解决的问题：修改时避免重新引入

**JPEG 色序。** 固定 Arduino ESP32 3.3.10 的实际解码链为 `esp_jpeg` 1.3.1、RGB888、`swap_color_bytes=0`，输出已是 RGB，不额外交换红蓝。较旧 camera 包的行为不同，不能从网上旧示例复制一次 R/B swap。换 SDK 后重新核对并用已知颜色验证。

**LCD 异步 DMA。** ST7789 使用 SPI3、mode0、20 MHz、RGB、反色开启、无镜像、无 XY 交换、无偏移。153,600 B 帧缓存在 PSRAM；7,680 B 暂存区在内部 DMA 内存，发送 RGB565 高字节后低字节。收到完成通知才复用暂存区；`draw_bitmap` 返回不等于传输完成。超时后停用显示但保留仍可能被 DMA/回调使用的对象，防止释放后使用。扫描线叠加在传输缓冲，不能污染原照片缓存。

**音频重播与扫描时钟。** 启动/重播依次停 I2S、重启合成器、清计数、预填充全部 4×256 帧、启用 I2S；IDF 5.5.4 的 disable/preload/enable 从 DMA 环首恢复。扫描线基于 `on_sent`，不是已生成/提交帧数；256 帧约 11.6 ms，屏幕最多约每 50 ms 更新。DMA 完成不是声学采样时间，用户正常反馈不等于已测量同步误差。

**断供处理。** I2S 自动清零后即使发送静音也会产生 `on_sent`。检测供数不足后停止、显示错误，不继续错误扫描或把截尾算作成功；最后一个跨越音乐终点的 DMA 块也要检测。不要只因为发送计数在增加就认定有有效音乐。

**按键。** 35 ms 消抖，短按释放后重播，长按约 650 ms 切换一次鼓点；长按释放不得补发短按。主循环可能被拍照阻塞，因此松开时需按持续时间补判长按。启动时已经按住的键先忽略到释放，时间计算要容忍 `millis()` 回绕。照片键播放时忽略，重播/鼓点键播放时可用。

## 新设备烧录边界

工具先识别设备、备份全片并验证，再写本地 `.local/device.json`；`prepare_device.py --check-profile` 可检查本地配置。`tools/flash.sh` 使用自己的配置并重新检查目标身份/分区；仅支持 NVS `0x9000/0x6000`、PHY `0xf000/0x1000`、factory `0x10000/0x100000`（地址/大小）的兼容布局，不兼容时拒绝。构建输出不超过 1 MiB 才可写应用。新端口可用 `FLASH_PORT` 覆盖，但身份必须匹配；不能改旧 profile 的 MAC 来冒充新板。不要下载或写入原作者全片备份；NVS 等内容也不应在设备间复制。

原设备出厂启动日志写 Flash 2 MB，但 esptool 和运行时为 16 MB；原工程在保留的 1 MiB 应用区实际启动成功。缺少 core dump 分区也属于原布局事实。新设备若出现类似文本，要检查自己的实测与布局，不能只按旧日志警告扩大分区或改启动程序。

## 故障排查路线与后续工作

按“连接 → 启动日志 → 外设状态 → 单次操作 → 连续测试 → 人的听音/观察”逐层收集证据：

1. 先区分 CH340 与原生 USB；关闭抢占端口的监视器，确认波特率 115200，释放 BOOT 后复位。
2. 读版本、Flash/PSRAM、相机 PID、`camera/audio/display` 和错误码；启动成功不意味着所有外设物理正常。
3. 相机失败核对 PSRAM/引脚/排线；屏幕失败断电核对 GND、针序、型号以及 USB 冲突；无声核对主板叠插和喇叭接口。
4. 用 `c` 一次完整拍照，再 `p` 重播、`d` 鼓点切换、`x` 停止；保存 `SONG`、`PLAY`、`STATUS`。未拍照重播提示错误是预期。
5. 跑设备脚本，再分别实按 BOOT/BUTTON1 与 BUTTON2；对比新板多轮计数、内存和 `underruns`，不要要求读数等于原板。
6. 若显示传输超时或音频断供，保留错误及最大耗时；不要在 ISR 做绘图/日志，也不要在播放循环引入整屏刷新或大块阻塞任务。
