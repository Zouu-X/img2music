## v0.3.0 五声音阶、颜色音色与鼓点

升级前先建立本地 Git 仓库：提交 `d502d25`、标签 `v0.2.0` 保存原始已验证实现；在 `feature/pentatonic-drums` 分支开发。旧版应用 `build/releases/v2m-v0.2.0.bin` 的 SHA-256 已重核，与后文 v0.2.0 摘要一致；完整出厂备份未改动。

本版仅增加 Drums 伴奏，默认关闭，不含 Bass / 琶音。音乐使用大小调五声音阶，每个竖条用加权颜色投票选择 Keys / Pluck / Flute / Bell；全图主音也由色相投票产生。两小节 4/4、16 个八分音符；鼓和旋律使用同一采样计数，开启等到下一个未生成的细分边界，关闭约 8 ms 渐弱。相机 BOOT / BUTTON1 用法保留，GPIO46 的 BUTTON2 短按重播，长按约 650 ms 切换鼓点。

`tools/test.sh` 在 AddressSanitizer / UndefinedBehaviorSanitizer 下通过：输入边界、五声音阶、颜色分区及互补色、四音色差异、任意分块一致性、鼓开关时序/渐弱、重播复现、100 ms 静音尾部、混音幅度；按钮消抖、短长按互斥、启动已按住忽略、时间回绕，以及阻塞跨过长按阈值后释放的回归。测试用例最高峰值 4121/32767，输出限制仍为 0.175 满幅；不是喇叭响度实测。

显示代码在临时模拟环境中通过 ASan/UBSan 检查：扫描后照片逐像素恢复、播放中重播归零、50 ms 节流、窄图边界及超时后的延迟回调。扫描不改变原照片缓存，通常传输一条窄区域和小段进度条。模拟布局已查看；实际屏幕观感仍须现场确认。

构建日志 `build/compile-v03.log`：代码 **445,849 B**、静态内存 **38,508 B**；应用 **446,000 B**。`build/flash-v03.log` 核对 MAC、完整备份和原分区，仅写 `0x10000` 应用区，独立校验通过。首次自动状态查询无响应，之后通过串口复位并取得正常启动日志 `build/boot-v03.log`；未确认首次不响应的具体原因。相机 PID 0x3660，屏幕/相机/音频均就绪，GPIO46 空闲为高。

应用归档 `build/releases/v2m-v0.3.0.bin`，SHA-256：


| 流程 | 结果 |

| 一次真实拍照、显示并播放；中途开启/关闭鼓点 | 完成，照片绘制 52 ms，拍照分析 739 ms |

## v0.2.0 屏幕版

- 屏幕由用户按 GND 对齐插入；采用商家配置的 ST7789、240×320 竖屏、RGB、反色开启、无镜像或 XY 交换、偏移 0。SPI3 20 MHz；背光 GPIO38 直接控制，不占用相机的 LEDC 计时器。
- 照片取自作曲使用的同一个 RGB888 缓冲，缩放为 240×180 保留完整比例。播放结束后保留照片；`j` 诊断导出不会替换屏幕上与旋律对应的照片。
- 中文状态为正在启动、等待拍照、正在拍照、正在播放、播放完成、已停止及操作失败。播放期间最多每 250 ms 更新一次小进度条；进度依据已提交音频帧，可能领先实际声音约一个 DMA 队列的长度，不作为精确音频时间戳。
- 显存 153,600 字节放在 PSRAM；7,680 字节 SPI DMA 暂存区放在内部内存，每批传输完成后才复用。异常时关闭显示、保留可能仍在使用的资源；不阻断相机和音频主流程。
- 固定文字采用 Noto Sans CJK SC Regular（OFL 1.1），十条文字位图共 2,613 字节；来源、许可和可重复生成脚本在 `assets/fonts/`、`tools/generate_ui_assets.py`。

`tools/flash.sh` 先编译，检查目标 MAC 和完整备份 SHA-256，读取设备分区并与备份、构建分区逐项比对，确认二进制不超过 1 MiB，才写入 `0x10000`。随后独立校验应用并复位。此次未改写启动程序、分区表、NVS 或 PHY 数据，未整片擦除。

出厂启动程序为 ESP-IDF `v4.4-dev-2594-ga20df743f1-dirty`，日志显示 Flash 2 MB；应用及 esptool 均检测 16 MB。当前应用保持在原 1 MiB 分区内，且实际启动成功。保留的分区表没有 core dump 分区，所以启动时出现 `No core dump partition found!`；本版不会将崩溃转储持久保存到 Flash。

备份实际恢复尚未演练。读取及摘要一致证明备份内容与当时设备一致，不能替代恢复验证。
